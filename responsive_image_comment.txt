## New Feature: Responsive Image Processing with SixLabors.ImageSharp (v2)

### Implemented Features

#### 1. Delete Old Image on New Upload
- When uploading a new cover, old image files are deleted from the uploads folder
- Prevents orphan file accumulation
- Extracts base slug from old URL and deletes all matching files

#### 2. Responsive Image Generation
- Generates two versions:
  - Mobile: max 640px width → slug-640.webp
  - Desktop: max 1280px width → slug-1280.webp
- Quality: 80 for both versions
- Aspect ratio preserved
- Original image discarded (only optimized versions saved)

#### 3. Slug-Based Naming (No GUID)
- Sanitize: lowercase, replace special chars with -, remove non-alphanumeric
- Empty/null/after-sanitize-empty slug → project (NOT image)
- Conflict resolution: slug-640.webp → slug-640-2.webp → slug-640-3.webp
- Same rule applies to both 640 and 1280 versions

#### 4. Relative URLs Preserved
- Returns: url, url640, url1280, fileName, size
- Frontend (SmartImage + resolveImage) works with -640 and -1280 pattern

### Changes Made
1. UploadController.cs: Added oldImageUrl parameter, uses SaveOptimizedResponsiveImageAsync
2. FileStorageService.cs: Added SaveOptimizedResponsiveImageAsync method
   - DeleteOldImageFiles() — removes old image files
   - SanitizeSlug() — slug sanitization (empty → project)
   - GetUniqueResponsiveFileName() — conflict resolution with counter
3. TestBase.cs: Updated SaveOptimizedResponsiveImageAsync stub
